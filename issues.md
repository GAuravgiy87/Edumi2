## 🔴 Critical Bugs

### BUG-001 — Missing `User` import in `video_views.py` (Runtime Crash)
**File:** `cameras/views_logic/video_views.py` — Lines 308–310
**Type:** NameError — crashes every request to `/cameras/teacher/<id>/`

The `teacher_profile` view calls `get_object_or_404(User, id=teacher_id)` but `User` is **never imported** at the top of the file.

```python
# Imports (lines 1–13) — User is missing!
from ..models import Camera, CameraRecording, RecordingChunk
from mobile_cameras.models import MobileCamera, MobileCameraPermission

# Line 310 — will throw NameError: name 'User' is not defined
teacher = get_object_or_404(User, id=teacher_id)
```
**Fix:** Add to top of file:
```python
from django.contrib.auth.models import User
```

### BUG-002 — WebSocket handler writes user data to disk in plain text
**File:** `meetings/consumers.py` — Lines 174–178
**Type:** Security / Data Leak

Every single WebSocket message is appended to `ws_debug.log` in the server's working directory. This writes **user IDs, usernames, and room codes** to disk indefinitely with no rotation.

```python
# Debug logging — left in production code
try:
    with open('ws_debug.log', 'a') as f:
        f.write(f"RECV: {self.user.id} ({self.user.username}) - {message_type} to {data.get('to_user_id')}\n")
except: pass
```
**Fix:** Remove this block entirely. Use `logger.debug(...)` gated by `settings.DEBUG` if needed.

### BUG-003 — `start_app.ps1` starts LiveKit **twice** (port conflict)
**File:** `start_app.ps1` — Lines 63 and 117–119
**Type:** Functional — duplicate process, port 7880 conflict

LiveKit is launched at Step [3/7] (line 63) and then again unconditionally at line 119. The second launch will fail silently or conflict with the first.

```powershell
# Line 63 — first launch (Step 3/7)
Start-Process -FilePath $LIVEKIT -ArgumentList "--config","config/livekit.yaml" -WindowStyle Minimized

# ... more steps ...

# Line 119 — DUPLICATE launch (no guard)
Start-Process -FilePath ".\livekit-bin\livekit-server.exe" -ArgumentList "--config", "config\livekit.yaml" -WindowStyle Normal
```
**Fix:** Delete lines 117–119 from the script.

### BUG-004 — Insecure `SECRET_KEY` hardcoded as default in settings
**File:** `school_project/settings.py` — Line 40
**Type:** Security — critical if deployed without env vars

```python
SECRET_KEY = os.environ.get('SECRET_KEY', 'django-insecure-@j!l-9t=qs!b&lkynb=zq$-h3f9d(_nm!hvctk$9ij()0kaja%')
```
The hardcoded fallback is used whenever the environment variable is absent, including on staging/production. Django's `django-insecure-` prefix is a warning that this key must never reach production.

**Fix:**
```python
SECRET_KEY = os.environ.get('SECRET_KEY')
if not SECRET_KEY:
    raise ImproperlyConfigured("SECRET_KEY environment variable is not set.")
```

### BUG-011 — All files import `User` directly instead of `get_user_model()`
**Files:** 20+ files across all apps
**Type:** Extensibility — breaks if `AUTH_USER_MODEL` is ever changed

Every app uses:
```python
from django.contrib.auth.models import User
```
Django's best practice is:
```python
from django.contrib.auth import get_user_model
User = get_user_model()
```
This becomes a hard breakage if a custom user model is introduced.
